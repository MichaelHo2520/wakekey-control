1為什麼需要 EMQX

公司的訪客 Wi-Fi 會擋掉所有連進來的連線，手機沒辦法直接連到 WakeKey。所以改成兩邊都主動連到雲端的同一台 MQTT broker（郵局），由它轉送訊息：

手機（控制網頁） ──WSS 8084──▶  EMQX  ◀──MQTT/TLS 8883── WakeKey ──USB── 電腦
  • EMQX Serverless 是 EMQX 官方代管的 broker，有每月免費額度，兩顆 WakeKey 全天在線只用掉約 9%。
  • 連線全程加密（TLS），每顆設備有自己的帳號，權限規則讓它只能碰自己的訊息。
  • 控制網頁用一個總管帳號 wk-admin，看得到所有設備。

會用到兩種登入，不要搞混：EMQX 帳號（你的 email，用來登入 EMQX 控制台、建帳號、看用量）和 MQTT 帳號（在控制台裡建的 wk-admin、office…，給控制網頁和板子連線用）。

2申請帳號、建立部署

  1. 到 accounts.emqx.com/signup 註冊：填名字、email、密碼和手機號碼（要收簡訊驗證），按 Start free trial，再到信箱點確認信。
  2. 登入 EMQX 控制台。第一次進去先建專案：Overview → + New Project，名稱例如 wakekey → Confirm。
  3. 按 New Deployment，方案選 Serverless。
  4. Spend Limit 保持 0（只用免費額度，永遠不會扣款）。
  5. 填部署名稱（例如 wakekey），專案選剛建的那個（之後不能改）。
  6. 勾選同意使用條款 → Deploy，等狀態變成 Running（約一兩分鐘）。

區域：Serverless 跑在 AWS／Google Cloud 的北美、歐洲、亞太。畫面上能選的話，選離你最近的亞太區，延遲最低。

3記下連線位址

點部署卡片進入 Deployment Overview，在 Connection Information 看得到：

欄位內容誰用
Address例如 xxxxxxxx.ala.asia-southeast1.emqxsl.com控制網頁登入、配對碼（控制網頁自動帶入）
Port 8883MQTT over TLSWakeKey 板子
Port 8084WebSocket over TLS（路徑 /mqtt）控制網頁

Serverless 只開 8883 和 8084，不支援 1883、8083，也不支援匿名登入。CA 憑證不用下載：WakeKey 和瀏覽器都用內建的憑證清單驗證。

4建立控制網頁帳號 wk-admin

  1. 左側選單 Access Control → Authentication → + Add。
  2. Username：wk-admin；Password：一組夠長的隨機密碼（建議 20 字以上）→ Confirm。

這組密碼等於所有電腦的鑰匙：拿到的人可以遠端叫醒、解鎖你的電腦。存在密碼管理器，不要傳給別人。

5設定權限（最重要）

EMQX Serverless 預設是「沒有規則擋就允許」，所以一定要加最後一條「拒絕全部」，否則任何一顆設備的帳號都能看、能控制其他設備。

選單 Access Control → Authorization（有些版本叫 Client Authorization），依下表順序新增三條：

#分頁對象TopicActionPermission
1Usernamewk-adminwakekey/#Publish & SubscribeAllow
2All Users—wakekey/${username}/#Publish & SubscribeAllow
3All Users—#Publish & SubscribeDeny
  • EMQX 先比對 Username 分頁的規則，再比對 All Users；All Users 裡先建的先比對。所以第 2 條一定要比第 3 條先建，順序錯了就要刪掉重建。
  • ${username} 會換成連線的帳號：帳號 office 只能用 wakekey/office/…。之後新增設備不用再改權限。

怎麼確認設對了：照第 7 節加好第一顆設備後，控制網頁看得到它而且能喚醒，就表示第 1、2 條沒問題；第 3 條擋住的是「設備之間互看」，平常感覺不到，照表設就好。

6登入控制網頁

  1. 打開 控制網頁（手機可以用瀏覽器的「加到主畫面」，之後像 App 一樣打開）。
  2. Broker 填第 3 節的 Address（只要主機名稱，不要 https:// 和埠號）；帳號 wk-admin；密碼是第 4 節那組。
  3. 勾「記住在這台裝置」就不用每次輸入（只存在這台手機的瀏覽器裡）。

7新增一顆 WakeKey

每顆設備一個 MQTT 帳號，帳號名稱就是設備代號（例如 office、home）。

  1. 控制網頁首頁 → 新增裝置：填名稱和代號（英文小寫、數字、-），選「新的板子」→ 下一步。網頁會產生隨機密碼和配對碼（wk1: 開頭）。這組密碼只顯示這一次，做完下面兩步再關。
  2. 到 EMQX 控制台 Access Control → Authentication → + Add，把網頁上的帳號、密碼（按複製鈕）貼進去 → Confirm。
  3. 把配對碼存進板子，三種方式任選：
    • 板子網頁（同一個網路時）：開板子的 IP（例如 http://192.168.31.233，路由器的裝置清單或控制網頁「概況」的 Wi-Fi 那列看得到） → 設定 → 雲端 → 貼上配對碼 → 儲存並重新開機。
    • 設定熱點（第一次安裝，例如公司那台）：手機連 WakeKey-Setup-XXXX 熱點 → 打開 http://192.168.4.1 → 選 Wi-Fi、輸入密碼，展開「雲端配對碼」貼上 → 測試並儲存。
    • UART 開發線：指令 pair wk1:…。
  4. 回到控制網頁，「等待中…」變成「已上線」就完成了。

配對碼裡含有這顆設備的密碼，當成密碼看待，不要貼在聊天群組。

8移除設備

  1. EMQX 控制台 Authentication → 找到該帳號 → 刪除（從此連不上）。
  2. 控制網頁裝置頁 → 設定 → 從清單移除。
  3. 板子本身（如果還要留著用）：板子網頁 設定 → 雲端 → 清除雲端配對。

9免費額度與費用

項目每月免費WakeKey 大約用多少
Session 分鐘（一個連線在線一分鐘＝1）100 萬每顆全天在線約 4.3 萬；兩顆約 9%
流量1 GB平常每月幾十 MB；每次遠端更新韌體約 2.3 MB
規則動作（Rule Actions）100 萬沒用到
  • Spend Limit 是 0 時永遠不會扣款；超過免費額度時部署會停到下個月，而且不會自己恢復，要到控制台手動重新啟動。
  • 用到免費額度的 75% 和碰到上限時，EMQX 會寄 email 通知。
  • 連續 30 天都沒有任何連線，部署會被停用；停用後 30 天內沒重新啟動可能會被刪除。WakeKey 平常一直在線，不會遇到。
  • 用量在 Deployment Overview 看（Session Minutes 約延遲 1 小時）。

10用 AI 快速新增設備（選用）

第 7 節要在兩個網站之間複製貼上。這一節改成：把下面的提示詞貼給 AI，它會下載小工具、幫你建好 EMQX 帳號，最後給你配對碼，你只要把配對碼貼進板子。

需要：一台有 Python 3 的電腦，加上一個能在你電腦上執行指令的 AI，例如 Claude Code、Claude 桌面版的 Code 模式。只能聊天的 AI（一般網頁版聊天）沒辦法執行，請改用第 7 節。

A. 第一次：建立 API Key（之後都不用再做）

API Key 是 EMQX 發給「程式」用的帳密（App ID ＋ App Secret）。程式沒辦法替你登入 EMQX 的網頁，所以要用它直接叫 EMQX 建帳號。

  1. EMQX 控制台 → 點你的部署 → Deployment Overview → Deployment API Key → + New API Key。
  2. 畫面顯示 App ID 和 App Secret。App Secret 只顯示這一次，先留在畫面上，等 AI 請你填設定檔時再複製進去（或先存進密碼管理器）。

API Key 可以管理整個 broker，跟 wk-admin 密碼一樣重要。只填進你電腦上的設定檔，不要貼到 AI 的對話裡；下面的提示詞也會要求 AI 不要跟你要密碼。

B. 每次新增：把提示詞貼給 AI

小工具：emqx_add_device.py（不含任何密碼；提示詞裡已經寫好下載網址，AI 會自己下載）。

請幫我在 EMQX 建立一顆 WakeKey 新設備的帳號。照下面的步驟做，每一步做完跟我說結果：

1. 在我的使用者資料夾裡建立資料夾 wakekey-tools（已經有就沿用），把
   https://michaelho2520.github.io/wakekey-control/emqx_add_device.py
   下載到裡面。之後的指令都在這個資料夾執行。
2. 確認電腦有 Python 3，然後執行：python -m pip install paho-mqtt
3. 如果資料夾裡還沒有 emqx.txt，執行：python emqx_add_device.py init
   然後請我自己用記事本打開 emqx.txt，填入 broker_host、wk-admin、api_app_id、api_app_secret 並存檔。
   重要：不要叫我把密碼或 API Key 貼在對話裡，也不要讀出、顯示或複製 emqx.txt 的內容。
4. 我說填好之後，執行：python emqx_add_device.py check
   有錯誤就用白話告訴我原因和怎麼修。
5. 問我新設備的「代號」（英文小寫、數字、-，2–16 字，例如 home）和「顯示名稱」（例如 家裡筆電），然後執行：
   python emqx_add_device.py add 代號 --name "顯示名稱"
6. 把印出的配對碼（wk1: 開頭）完整給我，提醒我它含有設備密碼，並告訴我把它貼到：
   板子網頁「設定 → 雲端 → 輸入配對碼」，或設定熱點頁的「雲端配對碼」。
7. 任何一步出現 404 或其他無法解決的錯誤，就停下來告訴我，並建議改用手動步驟：
   https://michaelho2520.github.io/wakekey-control/guide.html#device

小工具還有：python emqx_add_device.py list（列出帳號）、remove 代號（刪帳號並從控制網頁清單移除）。設定檔 emqx.txt 含密碼，請留在自己的電腦，不要上傳。

尚未驗證：EMQX 官方文件沒有列出 Serverless 方案「用 API 新增帳號」的功能，這個工具用的是 EMQX 5 的標準 API。第一次用時如果出現 404，表示這個方案不支援，請改用第 7 節。

11常見問題

控制網頁顯示「帳號或密碼錯誤」

確認帳號是 wk-admin、密碼是 EMQX 裡建的那組（不是你的 EMQX 登入密碼）；Broker 只填主機名稱。

板子網頁的雲端狀態是「帳號或密碼被拒絕」

EMQX 裡沒有這個設備帳號，或密碼不同。在控制網頁重新「新增裝置」產生新的配對碼，EMQX 裡的密碼也改成新的，再貼一次配對碼。

板子連上了，控制網頁卻看不到它

多半是權限：檢查第 5 節第 1 條（wk-admin 的 wakekey/#）有沒有建立。也可能是「新增裝置」選了「已經配對過」但代號打錯。

全部設備突然都離線

先看 EMQX 控制台部署是不是 Stopped（超過免費額度或 30 天沒連線），是的話手動重新啟動。

公司網路連得上嗎？

只要能上一般網站（HTTPS），通常 8883 和 8084 也通。若公司防火牆只開 443，目前的 Serverless 方案無法使用。

本頁依 EMQX Cloud 官方文件整理（2026-10-08）；控制台的按鈕名稱以英文介面為準，EMQX 改版時可能略有不同。
